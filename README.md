# C++ 算法与面试题练习

这是一个以 C++17 实现常见算法、数据结构和工程基础组件的练习仓库。代码按主题目录组织，适合已有 C++ 基础、希望系统整理面试解题模式和实现细节的开发者。

## 通用解题框架

不要从“我记得哪道题”开始，而要从问题约束和可维护的不变量开始。每道题建议按下面的顺序处理：

1. **澄清目标**：确认输入规模、数据范围、是否有序、是否允许修改输入、结果是否要求下标/路径/全部方案，以及无解时的返回约定。
2. **提取约束**：用 `N` 和数值范围估算可接受复杂度。通常 `N <= 20` 暗示回溯或状态压缩，`N <= 10^5` 优先考虑 O(N) 或 O(N log N)，超大数值范围要警惕溢出。
3. **抽象问题**：把题目归类为查找、计数、区间、最值、可达性、依赖关系、方案枚举或资源管理，再选择数组、哈希、栈、队列、堆、树、图或并查集。
4. **先写不变量**：明确每个指针、队列、哈希表、递归返回值或 DP 状态代表什么，以及每一步操作后它必须保持什么性质。
5. **选择优化方向**：暴力解用于确认定义；再通过排序、哈希、前缀和、双指针、单调结构、分治或缓存消除重复工作。不要为了套模板而忽略数据条件。
6. **验证正确性**：检查初始化、循环终止、边界移动、重复元素、空输入、极值、溢出和无解分支；能用归纳、反证或贪心交换论证解释关键步骤。
7. **落地为 C++**：明确所有权和生命周期，优先 RAII 与标准容器；关注迭代器失效、引用悬空、递归深度、异常安全、线程竞争和 `const` 正确性。
8. **复盘迁移**：记录“识别信号—核心不变量—复杂度—失败边界”，再把同一模式迁移到数组、字符串、链表和图等不同载体。

面试表达建议固定为：**定义问题 → 说明暴力 → 分析瓶颈 → 给出优化 → 解释不变量 → 证明正确性 → 报告复杂度 → 讲边界测试**。

## 学习顺序与解题思维

### 1. [数组、哈希与双指针](ArrayHashTest/ArrayHash.h)

目录：`ArrayHashTest/`。看到查找、去重、计数或区间统计，先问能否用哈希表记录历史状态；看到有序数组或两端向中间收缩，考虑双指针；看到大量区间和，考虑前缀和。滑动窗口要先确认窗口固定还是可变，再定义窗口状态、扩张条件和收缩条件。常见陷阱是忽略重复值、空输入，以及把只适用于正数的窗口收缩误用到含负数数组。

### 2. [二分查找、排序与区间](BinarySearchTest/BinarySearch.h)

目录：`BinarySearchTest/`、`MySortTest/`。先判断目标是否具有单调性：数组查值是位置单调，答案二分是可行性单调。明确区间采用 `[left,right]` 还是 `[left,right)`，写出循环不变量，再处理 `mid` 被排除的条件。区间题先按起点排序，维护当前合并区间；排序题还要说明稳定性、额外空间和是否允许修改输入。常见陷阱是死循环、整数溢出和边界重复计算。

### 3. [栈、队列、单调结构与堆](StackQueueTest/StackQueue.h)

目录：[`StackQueueTest/`](StackQueueTest/StackQueue.h)、[`MonotonicStackTest/`](MonotonicStackTest/MonotonicStack.h)、[`HeapTest/`](HeapTest/Heap.h)。先判断答案依赖顺序还是优先级：括号和撤销操作用栈，先进先出和层序遍历用队列，最近/下一个更大或更小用单调栈，窗口最值用单调队列，动态前 K 或多路合并用堆。实现时记录下标而非只记录值，明确元素何时过期、何时被淘汰。常见陷阱是队列中保存了不再属于窗口的下标。

### 4. [链表、树与递归](BinaryTreeTest/BinaryTree.h)

目录：[`MyListTest/`](MyListTest/MyList.h)、[`BinaryTreeTest/`](BinaryTreeTest/BinaryTree.h)。链表题先画指针变化，涉及倒数、第 K 个或环时优先考虑快慢指针；涉及反转、合并或分段时明确局部头尾和断链顺序。树题先判断是遍历、路径、层级、祖先还是子树信息，再选择 DFS、BFS 或递归返回状态。递归必须说明返回值含义、终止条件和当前节点的合并工作。常见陷阱是丢失后继指针、空根节点和递归栈过深。

### 5. [回溯、动态规划与贪心](BacktrackingTest/Backtracking.h)

目录：[`BacktrackingTest/`](BacktrackingTest/Backtracking.h)、[`DynamicProgrammingTest/`](DynamicProgrammingTest/DynamicProgramming.h)、[`GreedyTest/`](GreedyTest/Greedy.h)。回溯先定义每层可选项、路径状态、终止条件和撤销动作，存在重复值时先排序并剪枝。动态规划先写“状态代表什么”，再写转移、初始化、遍历顺序和空间压缩；如果状态依赖前缀或区间，要确认压缩后不会覆盖仍需使用的值。贪心要找出局部决策的可交换性或最远推进性质，并给出证明，不能只凭样例判断。常见陷阱是重复计数、初始化错误和剪枝改变答案空间。

### 6. [图论与并查集](GraphTest/Graph.h)

目录：[`GraphTest/`](GraphTest/Graph.h)、[`UnionFindTest/`](UnionFindTest/UnionFind.h)。先确定图是有向/无向、带权/无权，以及问题属于可达性、连通性、最短路、依赖还是生成树。无权最短路用 BFS，依赖关系用拓扑排序，非负权最短路用 Dijkstra，连通性动态合并用并查集。实现前明确访问标记和状态含义，检查环、重复边、不可达节点、负权和整数溢出。

### 7. [字符串、位运算与专项结构](MyStringTest/MyString.h)

目录：[`MyStringTest/`](MyStringTest/MyString.h)、[`ArrayHashTest/`](ArrayHashTest/ArrayHash.h)。字符串题先确认字符集、编码、大小写和空格规则；频次关系用哈希，前缀关系用 Trie，重复匹配再考虑 KMP 或字符串哈希。位运算题先画二进制位，区分异或消除成对元素、掩码提取位、移位构造范围和低位清零。常见陷阱是有符号移位、字符下标越界、编码与“字符数”概念不一致。

## 工程与 C++ 专项

[`LRUCacheTest/`](LRUCacheTest/LRUCache.h)、[`SharePtrTest/`](SharePtrTest/SharePtr.h)、[`SingletonTest/`](SingletonTest/LazySingleton.h)、[`ThreadTest/`](ThreadTest/ThreadPool.h)、[`TimerTest/`](TimerTest/Timer.h) 和 [`LogTest/`](LogTest/Logger.h) 用于练习资源所有权、生命周期、并发同步、线程安全和可观测性。设计这类组件时，先画出对象所有权和状态生命周期，再定义接口约束、异常路径和关闭流程；并发代码还要识别共享数据、建立同步边界、控制锁粒度并验证数据竞争。最后再讨论缓存策略、性能、可测试性和可观测性。

## 构建与验证

```powershell
cmake --preset windows-vs2022
cmake --build --preset windows-vs2022-debug
```

运行 `build/windows-vs2022/Debug/CodeForInterview.exe`。仓库暂无独立测试框架；新增算法应至少验证空输入、边界值、重复值、不可达或无解场景，并说明时间和空间复杂度。

## 代码约定

使用 C++17、四空格缩进、同一行大括号和主题目录命名。公共示例优先放在对应头文件的命名空间中，保持头文件自包含；提交前检查生成文件和二进制文件未被纳入版本控制。
